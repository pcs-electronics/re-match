# Plan for match-cli.py Script

## Overview
Create a Python script named `match-cli.py` to control the RigExpert Match Antenna Analyzer. The script should support basic commands like displaying help, checking connection status, and reading data from the analyzer.

## Key Requirements
1. **Command-Line Interface**: Display help when run without parameters or with `-h` or `--help`.
2. **Status Command**: Display the connection status of the analyzer.
3. **Read Data Command**: Return the desired range of R and X from the analyzer based on center frequency, range, and number of points. Support writing Touchstone output to a file via an output option; if not provided, output to stdout.
4. **Robustness**: Basic error handling for connection failures and read errors; exits with nonzero codes and prints diagnostics.
5. **Touchstone Format**: Output data in Touchstone format as seen in `test3.py` and `test4.py`.

## Communication Protocol
From the reference scripts (`test3.py` and `test4.py`), the RigExpert Match Antenna Analyzer uses a HID (Human Interface Device) interface for communication. The scripts use the `hid` library to send and receive data.

### Key Commands
- **FQ<fq>**: Set frequency (e.g., `FQ645001100` for 645 MHz).
- **SW<range>**: Set sweep range.
- **FRX<n>**: Start a sweep and read R and X values (takes several seconds).

### Data Format
- Data is sent as a list of bytes with a specific format: `[7, len(data)] + [ord(c) for c in data] + [0]*65`.
- Responses are read in chunks of 64 bytes.

## Script Structure

### 1. Command-Line Interface
- Use `argparse` to handle command-line arguments.
- Display help when no arguments are provided or when `-h` or `--help` is used.
- Include an example in the help message for the `read` command.

### 2. Status Command
- Check if the analyzer is connected by attempting to open a HID device with the vendor ID `0x0483` and product ID `0xa1de`.
- Return a meaningful message indicating whether the analyzer is connected or not.

### 3. Read Data Command
- Accept parameters: center frequency (default: 100 MHz), range (default: 200 MHz), and number of points (default: 100).
- Allow frequency input in kHz (e.g., `100k` or `100khz`) or MHz (e.g., `100m`, `100M`, or `100MHz`).
- Calculate the frequency range and send appropriate commands to the analyzer.
- Read and parse the R and X values from the analyzer.
- Return the data in Touchstone format (e.g., `! Touchstone file generated by match-cli.py on YYYY-MM-DD HH:MM:SS` followed by `# MHz Z RI R 50`).
- Add an output option to write Touchstone data to a file; if omitted, write to stdout.
- Support a `--trace` option to output raw data from the analyzer to stdout for debugging.
- Read responses after each command to ensure the device is ready for the next command.

### 4. Robustness
- Use try-except blocks to handle exceptions when the analyzer is disconnected or not responding.
- Return nonzero error codes and messages for failures (connection errors and read exceptions).
- Warn when fewer data points are received than requested.

## Example Usage

### Display Help
```bash
python match-cli.py -h
```

### Check Status
```bash
python match-cli.py status
```

### Read Data
```bash
python match-cli.py read --center 100MHz --range 200MHz --points 100
```

### Read Data to a File
```bash
python match-cli.py read --center 100MHz --range 200MHz --points 100 --output data.s1p
```

### Read Data with Trace
```bash
python match-cli.py read --center 100MHz --range 200MHz --points 100 --trace
```

## Error Handling
- **Connection Error**: Return error code `1` if the device cannot be opened.
- **Status Error**: Return error code `1` if the device is not connected.
- **Read Error**: Return error code `3` on exceptions during reads.

## Possible Enhancements
1. Add a retry mechanism for transient read errors.
2. Introduce a distinct data-parse error code.
3. Expand robustness for hot-plug disconnects during a sweep.
